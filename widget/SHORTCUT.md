# Быстрые команды iPhone: два рецепта

1. **«Честный тап»** — надиктовать трату наличными и увидеть карточку.
   Ниже, начиная с шага 0.
2. **«Скинуть скриншот»** — отправить картинку в разбор. Отдельный раздел
   в конце файла.

Обе команды ходят по одному и тому же личному ключу `X-Upload-Token`,
который выдаёт бот командой `/link`. Служебному ключу сервиса на телефоне
не место — см. следующий раздел.

Каждая собирается в приложении «Команды» за 3–4 минуты.
Экспортировать готовый `.shortcut` файлом нельзя: с iOS 15 система
принимает только команды, подписанные на устройстве, поэтому здесь
пошаговый рецепт, а не файл.

Названия действий даны по‑русски и по‑английски — в разных версиях iOS
перевод отличается, английское имя ищется поиском всегда.

---

## Что понадобится

| Что | Значение |
|---|---|
| Адрес сервиса | `https://look-own-alt-electronics.trycloudflare.com` |
| Ваш личный ключ | команда `/link` боту — **обе** команды ниже работают по нему |

Ключ ровно один, и он личный. Раньше в «Честный тап» предлагалось вшить
служебный `INGEST_API_KEY` из `.env` — так делать нельзя: этим ключом
пишут данные **за любого** пользователя, а телефон показывают друзьям и
отдают в сервис. Один показанный телефон — и отзывать пришлось бы общий
ключ, то есть сломать виджет сразу всем. Личный ключ говорит только «это
я», отзывается одной кнопкой и только свой.

Ключ живёт внутри команды, на телефоне владельца. В браузер он не попадает:
карточку страница открывает по отдельному токену, который сервер выдаёт в
ответе и который протухает через полчаса.

---

## Шаг 0. Новая команда

1. «Команды» → вкладка **Быстрые команды** → **+**.
2. Тап по названию вверху → **Переименовать** → `Честный тап`.
3. Там же **Выбрать значок**: цвет — зелёный, глиф — микрофон.
   (Свой рисунок значка виджет не поддерживает; своя картинка ставится
   только для иконки на рабочем столе, см. `README.md`.)

## Шаг 1. Надиктовать текст

Действие: **Надиктовать текст** (*Dictate Text*).

| Поле | Значение |
|---|---|
| Язык | Русский |
| Остановить прослушивание | **После паузы** (*After Pause*) |

Молчание — допустимый ответ: пустой текст сервер понимает как
«просто покажи, что там», трату не пишет и в счётчик действий не
записывает.

## Шаг 2. Отправить на сервер

Действие: **Получить содержимое URL‑адреса** (*Get Contents of URL*).

URL:

```
https://look-own-alt-electronics.trycloudflare.com/api/v1/quick/tap
```

Раскрыть **Показать больше** (*Show More*) и заполнить:

| Поле | Значение |
|---|---|
| Способ (*Method*) | `POST` |
| Заголовки (*Headers*) → ключ | `X-Upload-Token` |
| Заголовки → значение | ваш личный ключ `fm_…` из `/link` |
| Тело запроса (*Request Body*) | **JSON** |

В теле — одно поле (кнопка **Добавить новое поле**):

| Тип | Ключ | Значение |
|---|---|---|
| Текст (*Text*) | `text` | переменная **Надиктованный текст** |

`tg_id` в теле больше не нужен: кто вы — говорит ключ. Если он там
остался от старой версии команды, сервер его просто не станет слушать.

## Шаг 3. Достать ссылку на карточку

Действие: **Получить значение из словаря** (*Get Dictionary Value*).

| Поле | Значение |
|---|---|
| Получить | Значение (*Value*) |
| Для ключа | `card_url` |
| В | **Содержимое URL‑адреса** (результат шага 2) |

## Шаг 4. Показать карточку

Действие: **Показать веб‑страницу** (*Show Web Page*) с переменной
**Значение из словаря**.

Открывается поверх рабочего стола, закрывается смахиванием вниз —
человек не уходит в браузер и не теряет место, где был.

> Если «Показать веб‑страницу» в вашей версии нет, подойдёт
> **Открыть URL‑адреса** (*Open URLs*) — разница только в том, что
> откроется полноценный Safari.

---

## Готовая команда целиком

```
1. Надиктовать текст            (язык: русский, остановка: после паузы)
2. Получить содержимое URL      POST  …/api/v1/quick/tap
                                Header  X-Upload-Token: fm_<ваш ключ>
                                JSON    text: <Надиктованный текст>
3. Получить значение из словаря  card_url
4. Показать веб-страницу         <Значение из словаря>
```

## Вариант «совсем без экрана» (3 действия)

Кому не нужна карточка — шаги 3 и 4 заменяются одним:

**Показать уведомление** (*Show Notification*) со значением ключа
`notification`. Сервер уже собрал готовую строку:

```
Записал: кофе — 300 ₽ · Сентябрь 2026: 125 918,20 ₽ · осознанность 99 % · вопрос: 1
```

---

## Запасной вариант, пока `quick.py` не подключён

`/api/v1/quick/*` появляется после одной строки в `app/api/app.py`
(см. `README.md`). Пока её нет, тот же тап работает через уже живой
эндпоинт заливки — карточки не будет, запись наличных будет:

```
1. Надиктовать текст
2. Получить содержимое URL   POST  …/upload  (текст не примет)
                             — запасного пути для диктовки без quick.py нет:
                               `/api/v1/ingest/expense` ходит по служебному
                               ключу, а ему на телефоне не место
3. Показать уведомление      «Записано»
```

# Вторая команда: «Скинуть скриншот»

Отправляет картинку (скриншот списка операций или фото чека) в `POST
/upload`, где она сразу разбирается в операции. Адрес приёма один на всех
телефонах, поэтому опознаёт вас не адрес, а личный ключ в заголовке.

Раньше здесь стоял `tg_id`, и это было небезопасно: telegram id не секрет —
его видит каждый, кому вы писали, и его можно перебрать. С таким «опознанием»
посторонний мог залить операции в вашу книгу и испортить ваши цифры.
Если ваша команда собрана по старой инструкции — пересоберите шаг 2:
`tg_id` теперь молча игнорируется, файл сохранится, но никому не
засчитается.

## Шаг 1. Взять ключ

Напишите боту `/link`. В ответе — адрес и ключ вида `fm_…`, а под ними
кнопка «Выпустить новую»: если ключ куда-то утёк, нажмите её, и старый
перестанет работать сразу.

Ключ личный. Кто его получит — сможет добавлять операции в вашу книгу.
Не пересылайте готовую команду друзьям: внутри неё ваш ключ. Делитесь
этой инструкцией, а ключ каждый берёт свой.

## Шаг 2. Собрать команду

«Команды» → **+** → назвать `Скинуть скриншот` → добавить два действия.

**Действие 1: Снимок экрана** (*Take Screenshot*) — или **Выбрать
фото** (*Select Photos*), если присылать хотите готовое фото чека.

**Действие 2: Получить содержимое URL-адреса** (*Get Contents of URL*),
раскрыть **Показать больше** (*Show More*):

| Поле | Значение |
|---|---|
| URL | `https://look-own-alt-electronics.trycloudflare.com/upload` |
| Способ (*Method*) | `POST` |
| Заголовки → ключ | `X-Upload-Token` |
| Заголовки → значение | ваш ключ `fm_…` из `/link` |
| Тело запроса (*Request Body*) | **Файл** (*File*) |
| Файл | переменная **Снимок экрана** |

Заголовок и тело-файл сочетаются нормально: тип тела на заголовки не
влияет. Если удобнее стандартный заголовок — подойдёт
`Authorization` со значением `Bearer fm_…`.

> **Не кладите ключ в адрес** (`?token=fm_…`). Так тоже работает, но полный
> URL со строкой запроса пишут в журнал все прокси подряд, включая
> cloudflared, а «ссылкой» легко поделиться целиком, не заметив, что отдали
> вместе с ней доступ. Заголовок — ровно на одно поле больше при настройке,
> один раз.

## Шаг 3 (необязательный). Показать, что распозналось

**Получить значение из словаря** (*Get Dictionary Value*) с ключом `added`
и **Показать уведомление** (*Show Notification*).

Одного `added` мало: если вы прислали тот же скриншот второй раз (а так
и бывает — список операций пересекается с прошлым разом), новых операций
не добавится и уведомление честно покажет «0». Поэтому берите два поля и
складывайте строку сами:

```
добавлено {added}, уже было {duplicates}
```

Остальные поля ответа: `recognized` — сколько операций видно по этому
файлу всего, включая уже известные; `batch_id` — номер загрузки, по
нему экран «Что я присылал» покажет, что из неё вышло; `new_questions` —
сколько вопросов она подняла; `ingested` — прочиталось ли вообще;
`warning` — появляется, только если что-то не так с самим запросом
(например, ключ уехал в адрес).

## Назначить на двойное касание

Настройки → Универсальный доступ → Касание → Касание задней панели →
Двойное касание → выбрать `Скинуть скриншот`.

## Проверка ключа без телефона

```bash
curl -s -X POST https://<адрес>/upload \
  -H "X-Upload-Token: fm_ваш_ключ" \
  -H "Content-Type: image/png" --data-binary @shot.png
```

Готовая строка с подставленным ключом лежит в поле `curl` ответа
`GET /api/v1/me/upload-link`.

---

## Проверка без телефона

```bash
curl -s -X POST https://<адрес>/api/v1/quick/tap \
  -H "X-Upload-Token: fm_ваш_ключ" \
  -H "Content-Type: application/json" \
  -d '{"text": "кофе 300"}'
```

В ответе — `headline`, `card_url`, `notification` и весь остальной состав
карточки. Открыть `card_url` в браузере — то же, что увидит телефон.

## Если не работает

| Симптом | Причина |
|---|---|
| `405 Method Not Allowed` на `/api/v1/quick/tap` | роутер подключён **после** `app.mount("/", StaticFiles…)`; статика на корне перехватывает всё, что добавлено после неё |
| `401 ссылка не опознана` на тапе | не тот `X-Upload-Token`: возьмите свежий командой `/link`, в заголовке не должно быть пробелов по краям |
| `401 ссылка не опознана` на `/upload` | ключ `X-Upload-Token` не тот, устарел или отозван кнопкой «Выпустить новую» — возьмите свежий командой `/link` |
| Файл принят, но операции не появились | в команде нет заголовка `X-Upload-Token` (или остался старый `tg_id`): без ключа файл просто сохраняется, как и написано в ТЗ |
| Операции ушли «не туда» | в команду вставлен чужой ключ — у каждого человека свой |
| Файл не открывается по ссылке из ответа | ссылка на личный файл подписана и живёт несколько часов; свежую даёт `GET /api/v1/me/imports` или повторная загрузка |
| `503 виджет выключен` | на сервере нечем подписать карточку: пусты и `BOT_TOKEN`, и `INGEST_API_KEY` |
| «Ссылка больше не действует» | токен карточки старше получаса — нажать виджет ещё раз |
| Диктовка не появляется | в «Команды» → настройки команды разрешить доступ к микрофону и распознаванию речи; первый раз команду надо запустить вручную из приложения |
| Трата не записалась | в надиктованном нет числа. Говорить надо «кофе 300», а не «кофе за триста» |
