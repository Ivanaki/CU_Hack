# HTTP API «Честного месяца»

Базовый URL локально — `http://localhost:8080`, порт задаётся `API_PORT`.
Живая схема OpenAPI и песочница — `/docs`. Всё, что ниже, взято из
`app/api/routes.py` и `app/api/schemas.py`; примеры ответов — реальные,
снятые с демонстрационного набора (сентябрь 2026).

## Две группы эндпоинтов

| Группа | Префикс | Аутентификация | Кто ходит |
|---|---|---|---|
| Mini App | `/api/v1/me/*` | `X-Telegram-Init-Data` | Telegram Mini App от имени пользователя, только свои данные |
| Служебная заливка | `/api/v1/ingest/*` | `X-API-Key` | наш же внешний сервис, может писать данные **любому** пользователю |
| Служебное | `/healthz` | нет | мониторинг, HEALTHCHECK контейнера |

Смешивать группы нельзя: по служебному ключу можно писать за кого угодно, и
он никогда не должен оказаться в браузере.

### `X-Telegram-Init-Data` — подпись Telegram

В заголовок кладётся значение `Telegram.WebApp.initData` целиком, как есть
(url-encoded строка). Сервер проверяет подпись по алгоритму из документации
Telegram: из токена бота выводится ключ `HMAC_SHA256("WebAppData", token)`,
им подписывается строка из отсортированных пар `key=value`, результат
сравнивается с `hash`. Дополнительно проверяется свежесть: `auth_date`
старше 24 часов — `401`.

```
X-Telegram-Init-Data: query_id=AAExample&auth_date=1790000000&user=%7B%22id%22%3A1%7D&hash=6f2c...
```

Возможные ответы: `401 нет initData`, `401 в initData нет подписи`,
`401 подпись initData не сходится`, `401 initData просрочена`,
`401 в initData нет пользователя`. Пользователь заводится при первом
успешном запросе, имя берётся из `first_name`/`last_name`/`username`.

**Отладочный путь.** Если `BOT_TOKEN` пуст (локальная разработка, подписывать
initData нечем), вместо подписи принимается `X-Debug-Tg-Id: <число>`. Как
только токен задан, этот путь закрыт — в рабочей конфигурации им
воспользоваться нельзя.

### `X-API-Key` — служебный ключ

Значение сравнивается с `INGEST_API_KEY` через `hmac.compare_digest`.

- ключ в конфиге не задан → `503 служебный API выключен: не задан INGEST_API_KEY`
  (вся группа `/api/v1/ingest/*` выключена);
- ключ не совпал или заголовка нет → `401 неверный X-API-Key`.

## Формат денег

Любая денежная величина в ответе — объект из двух полей:

```json
{ "kopecks": 12561820, "text": "125 618,20 ₽" }
```

`kopecks` — целое число копеек со знаком, единственный источник правды для
расчётов. Внутри системы деньги вообще нигде не хранятся во float: «0.1 + 0.2»
в отчёте о финансах — самый быстрый способ потерять доверие к цифрам.

`text` — уже отформатированная строка, чтобы клиенту не пришлось повторять
логику разделителей и округления, а бот, Mini App и сторонний интегратор
показывали одно и то же. Разделитель разрядов и отступ перед знаком рубля —
узкий пробел U+2009, дробная часть отделена запятой и опускается, когда
копеек нет (`"301 240 ₽"`). Для дельт формат со знаком: `"+12 635,20 ₽"`.

## Ошибки

Ошибки транспорта и доступа возвращаются как обычный `HTTPException`
FastAPI: `{"detail": "текст"}` с кодами `400`, `401`, `404`, `413`, `503`.

Ошибки *содержательные* — когда запрос корректен, но данные не разобрались —
возвращаются с кодом `200` в теле `IngestResultOut`: `ok: false` и человеческий
текст в `error`. Это сделано намеренно: «не смог прочитать картинку» — не
сбой интеграции, а нормальный исход, на который у клиента есть сценарий.

## `POST /api/v1/me/questions/{review_id}/answer`

Ответ одним тапом. Записывает решение пользователя и **сразу запускает
полный пересчёт**, поэтому после ответа все цифры уже новые.

Тело: `{"code": "<код выбранного варианта>"}`, 1…64 символа. Код берётся из
`options[].code` того же вопроса.

```bash
curl -s -X POST "http://localhost:8080/api/v1/me/questions/2/answer" \
  -H "X-Telegram-Init-Data: $INIT_DATA" \
  -H "Content-Type: application/json" \
  -d '{"code": "debt_back"}'
```

```json
{ "ok": true, "awareness_percent": 99, "open_questions": 1, "streak_days": 1 }
```

`awareness_percent` — процент осознанности после пересчёта, округлённый до
целого: на мелком вопросе он может и не сдвинуться, зато
`awareness.unknown` в `/summary` уменьшится на сумму разобранной операции.
`streak_days` — серия дней, которая только что продлилась этим действием.

`404 вопрос не найден или уже закрыт` — если вопрос чужой, не существует или
уже отвечен. Для `shared_bill_heads` код должен быть числом; `more` вернёт
`404`, потому что число участников из него не выводится.

## `POST /api/v1/me/questions/{review_id}/skip`

Отложить вопрос. Сумма останется неразобранной, процент осознанности не
вырастет.

```bash
curl -s -X POST "http://localhost:8080/api/v1/me/questions/1/skip" \
  -H "X-Telegram-Init-Data: $INIT_DATA"
```

```json
{ "ok": true, "open_questions": 0 }
```

Этот эндпоинт всегда отвечает `200`, даже если вопроса с таким id нет или он
принадлежит другому пользователю: отложить несуществующее — не ошибка.

# Служебная заливка: `/api/v1/ingest/*`

Все эндпоинты группы требуют `X-API-Key` и принимают `tg_id` — Telegram id
пользователя, за которого заливаются данные.

## `POST /api/v1/ingest/screenshot`

Главный эндпоинт для стороннего сервиса, который шлёт нам картинки
пользователей.

**Формат.** `multipart/form-data`.

| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| `tg_id` | int (form) | да | Telegram id пользователя |
| `files` | файлы | да | одна или несколько картинок |
| `display_name` | строка (form) | нет | имя, проставляется только если у пользователя его ещё нет |

**Несколько файлов.** Повторяйте поле `files` — имя поля одно и то же для
всех картинок:

```bash
curl -s -X POST "http://localhost:8080/api/v1/ingest/screenshot" \
  -H "X-API-Key: $INGEST_API_KEY" \
  -F "tg_id=1058389184" \
  -F "display_name=Сергей К." \
  -F "files=@shot1.png" \
  -F "files=@shot2.png" \
  -F "files=@shot3.png"
```

Все присланные картинки уходят в модель **одним запросом** и разбираются как
один экран, продолжающийся на несколько скриншотов: если пользователь
отснял список операций тремя кадрами, операции не задвоятся на границах.

**Ограничения.** Берутся первые **10** файлов, остальные молча
игнорируются. Каждый файл — не больше **12 МБ**, иначе
`413 <имя файла> велик`. Пустые файлы отбрасываются; если не осталось ни
одного непустого — `400 пустая загрузка`.

**Что возвращается.** `IngestResultOut` — та же форма, что у всех эндпоинтов
заливки. Числа в примере зависят от картинки, поля — нет:

```json
{
  "ok": true,
  "source": "Т-Банк",
  "added": 8,
  "duplicates": 1,
  "superseded": 0,
  "operations": 110,
  "questions": 3,
  "unresolved": { "kopecks": 50000, "text": "500 ₽" },
  "error": ""
}
```

| Поле | Что значит |
|---|---|
| `ok` | удалось ли что-то распознать и загрузить |
| `source` | что распознала модель: название банка со скриншота или магазина с чека |
| `added` | сколько новых сырых операций легло в базу |
| `duplicates` | сколько отброшено как уже известные (точный хеш либо мягкое совпадение с выпиской) |
| `superseded` | сколько ранее присланных картинкой записей уточнено более точным источником |
| `operations` | сколько всего операций у пользователя после пересчёта (не сколько добавлено) |
| `questions` | сколько спорных операций ждут ответа |
| `unresolved` | сумма, смысл которой не установлен |
| `error` | человеческий текст при `ok: false` |

Картинка распознаётся и как скриншот приложения банка, и как кассовый чек —
выбирать вид не нужно, это делает модель. С чека берётся одна операция на
сумму ИТОГО, состав покупки уходит в описание.

**Если пользователь ещё не заведён** — он создаётся по `tg_id` прямо в этом
запросе, вместе с `display_name`, если он передан. Заливать можно до того,
как человек вообще написал боту: когда он придёт и нажмёт `/start`, данные
уже будут на месте, разобраны и с готовой очередью вопросов. Отдельного
эндпоинта регистрации нет и не нужно.

**Если распознать не удалось** — `200` с `ok: false`:

```json
{
  "ok": false, "source": "", "added": 0, "duplicates": 0, "superseded": 0,
  "operations": 0, "questions": 0, "unresolved": null,
  "error": "не удалось прочитать операции на картинке"
}
```

Так же выглядит ответ, когда языковая модель выключена (`LLM_PROVIDER=none`)
или недоступна: чтение картинок — единственная функция, которая без модели
не работает. Разумная реакция клиента — попросить пользователя прислать
CSV-выписку.

## `POST /api/v1/ingest/statement`

CSV-выписка за пользователя. `multipart/form-data`, поля `tg_id`, `file`
(ровно один файл), `display_name`.

```bash
curl -s -X POST "http://localhost:8080/api/v1/ingest/statement" \
  -H "X-API-Key: $INGEST_API_KEY" \
  -F "tg_id=1058389184" \
  -F "file=@data/demo/tbank_2026-07_09.csv"
```

```json
{
  "ok": true, "source": "Т-Банк",
  "added": 98, "duplicates": 0, "superseded": 0,
  "operations": 98, "questions": 3,
  "unresolved": { "kopecks": 1050000, "text": "10 500 ₽" },
  "error": ""
}
```

Это реальный ответ на демонстрационную выписку Т-Банка, залитую в одиночку.
Неразобранных 10 500 ₽ — хорошая иллюстрация того, как система ведёт себя с
неполными данными: перевод 10 000 себе на Альфу без второй половины пары
остаётся переводом физлицу с неизвестным смыслом и честно висит как
«не разобрано», а не записывается тратой. Как только придёт выписка Альфы,
пара склеится и неразобранных останется 500 ₽.

Повторная заливка того же файла безопасна — все строки уедут в `duplicates`:

```json
{
  "ok": true, "source": "Т-Банк",
  "added": 0, "duplicates": 98, "superseded": 0,
  "operations": 98, "questions": 3,
  "unresolved": { "kopecks": 1050000, "text": "10 500 ₽" },
  "error": ""
}
```

Формат определяется по заголовку файла: Т-Банк, Сбербанк, Альфа-Банк и
канонический CSV. Неузнанный формат — `200` с текстом, по которому видно,
что именно не подошло:

```json
{
  "ok": false, "source": "", "added": 0, "duplicates": 0, "superseded": 0,
  "operations": 0, "questions": 0, "unresolved": null,
  "error": "не узнал формат выписки 'junk.csv'; колонки: ['a', 'b', 'c']"
}
```

Файл больше 12 МБ — `413 файл велик`.

# Загрузки с шортката iPhone: `/upload`, `/files`

Команда сделала шорткат: двойное касание по задней панели телефона делает
скриншот или голосовую запись и отправляет файл сюда. Это вход для данных
пользователя, а не файлохранилище — если рядом с картинкой пришёл `tg_id`,
она сразу разбирается в операции.

Ключа по умолчанию нет: пустой `UPLOAD_API_KEY` оставляет приём открытым,
как и написано в ТЗ шортката. На публичном адресе ключ стоит задать — тогда
`POST /upload` и `GET /files` требуют `X-API-Key`, а ссылка на конкретный
файл продолжает открываться без него (иначе она бесполезна).

## `POST /upload`

Два способа прислать файл, оба возвращают один и тот же JSON.

**Способ 1 — форма.** Файл в поле `file`:

```bash
curl -s -X POST "$BASE/upload" -F "file=@shot.png"
```

**Способ 2 — файл прямо в теле.** Имя в query-параметре `filename` или в
заголовке `X-Filename`, тип — в `Content-Type`. Ради шортката: он умеет POST
с файлом в теле, но не умеет собирать multipart.

```bash
curl -s -X POST "$BASE/upload?filename=shot.png" \
  -H "Content-Type: image/png" --data-binary @shot.png
```

```json
{
  "filename": "image.png",
  "stored_as": "f863e43293094215b5d71fec9363037e.png",
  "content_type": "image/png",
  "size": 677432,
  "url": "https://api.example.com/files/f863e43293094215b5d71fec9363037e.png"
}
```

**Поддерживаемые типы.** `image/jpeg`, `image/png`, `image/webp`,
`image/heic`, `image/heif`, `audio/mpeg`, `audio/ogg`, `audio/wav`,
`audio/webm`, `audio/mp4`, `audio/x-m4a`.

**`application/octet-stream` тоже принимается** — формат в этом случае
определяется по сигнатуре содержимого (magic bytes), а не по имени файла.

**Сигнатура решает всегда, а не только при `octet-stream`.** Файл, названный
`image/png`, но начинающийся с `FF D8 FF`, будет сохранён как JPEG. Если
сигнатуру опознать не удалось — `415`, каким бы типом файл ни назвали: у всех
одиннадцати поддерживаемых форматов сигнатура есть, поэтому неопознанные
байты означают формат не из списка, а не «экзотический, но валидный файл».
Заявленный тип не добавляет в список ничего нового и выигрывает ровно в
одном случае: когда называет тот же формат другим именем (`audio/x-m4a`
и `audio/mp4`). У mp3 сигнатур две — тег `ID3` и синхрослово фрейма MPEG, —
обе распознаются, отдельной поблажки для него не требуется.

Практический смысл: HTML, обычный текст, PDF, ZIP или windows-исполняемый
файл нельзя залить под видом `image/png`. Раньше это проходило, и `/files/`
превращался в раздатчик произвольных файлов со ссылкой на домене проекта.

**Имя файла из запроса никуда, кроме поля `filename` в ответе, не попадает.**
На диск файл ложится под именем `UUID.расширение`, расширение берётся из
определённого типа. Прислать `../../evil.php` безопасно: имя вернётся в
ответе как есть, а файл окажется обычным `<hex>.png` внутри каталога
загрузок.

**Ошибки.**

| Код | Когда |
|---|---|
| `400` | пустой файл или испорченная multipart-форма |
| `413` | больше `MAX_UPLOAD_MB` (по умолчанию 20 МБ) |
| `415` | формат не поддерживается или сигнатура содержимого не опознана |
| `422` | в multipart нет поля `file` |
| `401` | задан `UPLOAD_API_KEY`, а заголовок `X-API-Key` не совпал |

Тело читается потоком, и приём обрывается ровно на лимите: сервер не станет
принимать гигабайт, чтобы потом ответить `413`. Если клиент прислал
`Content-Length` больше лимита, отказ приходит до чтения тела.

**Необязательный разбор картинки.** Если в запросе есть `tg_id` (query-параметр,
поле формы или заголовок `X-Tg-Id`) и файл — картинка, она дополнительно
прогоняется через тот же разбор, что и `/api/v1/ingest/screenshot`. В ответе
появляются три необязательных поля, обязательные пять не меняются.

```bash
curl -s -X POST "$BASE/upload?filename=shot.png&tg_id=1058389184" \
  -H "Content-Type: image/png" --data-binary @shot.png
```

```json
{
  "filename": "shot.png",
  "stored_as": "f863e43293094215b5d71fec9363037e.png",
  "content_type": "image/png",
  "size": 677432,
  "url": "https://api.example.com/files/f863e43293094215b5d71fec9363037e.png",
  "ingested": true,
  "operations": 98,
  "questions": 3
}
```

`ingested` — удалось ли прочитать операции; `operations` и `questions`
описывают состояние после пересчёта, как и везде в этом API, а не дельту.
Пользователь заводится по `tg_id` при первом обращении.

Разбор никогда не влияет на код ответа: файл уже сохранён, и ошибка модели
даёт `ingested: false`, а не `500`. Без `tg_id`, с `analyze=false` или для
звука необязательных полей в ответе просто нет. Отдельно про формат: в модель
зрения картинка уходит с ярлыком `image/png`, поэтому HEIC с iPhone
разбирается ненадёжно — в шорткате его лучше конвертировать в JPEG.

## `GET /files`

```json
{
  "files": [
    {
      "name": "f863e43293094215b5d71fec9363037e.png",
      "size": 677432,
      "url": "https://api.example.com/files/f863e43293094215b5d71fec9363037e.png"
    }
  ]
}
```

Свежие сверху. В список попадают только файлы с нашим именем — всё
постороннее, что оказалось в каталоге, игнорируется.

## `GET /files/{filename}`

Содержимое файла. Имя проходит две независимые проверки: строгую регулярку
(32 hex-символа и известное расширение) и сравнение `resolve()`-пути с
каталогом загрузок. Не прошло — `404`, без разницы, чем именно это было:
`../`, `..%2F`, абсолютным путём или нулевым байтом.

Файл отдаётся с правильным `Content-Type`, заголовком
`X-Content-Type-Options: nosniff` и `Content-Disposition: inline` с
безопасным именем. Без этого загруженный «png» мог бы оказаться
HTML-страницей с чужим скриптом, выполненным на нашем домене.

## Где лежат файлы

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `UPLOAD_DIR` | `./data/uploads` | каталог загрузок; относительный путь — от корня проекта, то есть от `/app` в контейнере |
| `MAX_UPLOAD_MB` | `20` | лимит размера |
| `PUBLIC_BASE_URL` | пусто | базовый адрес для поля `url`; пусто — соберётся из заголовков прокси или адреса запроса |
| `UPLOAD_API_KEY` | пусто | пусто — приём открыт; иначе нужен `X-API-Key` |

Каталог примонтирован именованным томом `honest-uploads` (см.
`docker-compose.yml`), поэтому файлы переживают пересборку образа,
`docker compose down` и передеплой — ровно как база в томе `honest-data`.

`PUBLIC_BASE_URL` нужен настройкой, а не берётся из запроса: снаружи сервис
стоит за туннелем и приходит по `https`, а внутрь запрос попадает по `http`,
и `request.base_url` вернул бы ссылку, которая в браузере не открывается.
Адрес quick-туннеля меняется при каждом перезапуске — правится в `.env` на
сервере и подхватывается рестартом контейнера, без пересборки образа.

Если настройку всё-таки забыли, адрес собирается из `X-Forwarded-Proto` и
`X-Forwarded-Host`, а уже потом из `request.base_url`. Читаем эти заголовки
сами, потому что uvicorn по умолчанию доверяет им только с `127.0.0.1`
(`forwarded_allow_ips="127.0.0.1"`), а cloudflared в docker приходит с адреса
сети контейнеров — то есть ровно в боевой конфигурации заголовок
игнорировался бы и ссылка уезжала в `http` на `https`-входе. В `X-Forwarded-Host`
пускается только то, что похоже на имя хоста; всё остальное отбрасывается, и
берётся хост запроса.

**Если перед сервисом появится Nginx** (сейчас его нет — наружу смотрит
cloudflared), ему нужно поднять лимит тела запроса, иначе он отрежет загрузку
раньше приложения и вернёт свою `413` вместо нашей:

```nginx
client_max_body_size 20M;
```

# Заметки для интегратора

- **CORS** открыт (`*`) для методов `GET`, `POST`, `OPTIONS`: Mini App живёт
  на домене Telegram и ходит сюда из браузера. Middleware один на всё
  приложение, загрузки с шортката он покрывает тоже.
- **Сервер слушает `0.0.0.0`** (`API_HOST`), порт — `API_PORT`.
- **Любая заливка запускает полный пересчёт** классификации для этого
  пользователя. Поэтому поля `operations`, `questions` и `unresolved` в
  ответе описывают состояние после пересчёта, а не дельту.
- **Дедупликация двухуровневая.** Один и тот же факт, присланный сегодня
  картинкой и через месяц приехавший в выписке, засчитывается один раз;
  выигрывает выписка как более точный источник. Слать одно и то же дважды
  безопасно.
- **Порядок заливки не важен.** Классификация — чистая функция от сырых
  данных и решений пользователя, результат не зависит от того, что приехало
  раньше.
- **Ответы на вопросы переживают перезаливку.** Решение привязано к хешу
  сырой строки, а не к id операции, так что уточнение данных не заставит
  пользователя отвечать на один вопрос дважды.
